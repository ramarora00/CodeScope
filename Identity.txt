**Perspective 1 — Understanding**

**Visual hierarchy**

**Typography**

Inter/Geist mix fine. Enforce: Geist Mono ONLY for code/data, Inter for narration/AI voice. Never mix within same sentence — keeps "AI speaking" register distinct from "AI reading code" register.

**Spacing**

Whitespace = confidence signal. Don't fear dead space around findings — cramped panels read as "trying too hard," premium tools breathe.

**Timing**

Fast enough not to bore (~150-250ms micro), slow enough to read as intentional for major transitions (400-600ms). Nothing instant — instant = mechanical, not thoughtful.

**Psychology**

User's anxiety = "is AI actually smart or just animating." Counter via specificity — findings must cite real line numbers/symbols immediately, not vague summaries first. Trust built via evidence density early.

**AI personality**

Should read: quietly competent, terse, confident senior engineer. NOT chipper assistant. No exclamation points, no "Great question!" — captions should sound like real engineer's inner notes.

**Emotional journey**

Curiosity (onboarding) → trust (watching investigate) → satisfaction (evidence accumulates) → closure (report). Each perspective transition = journey beat, not menu switch.

**Disconnection risk**

Biggest: if panels update independently w/o visual linkage, feels like separate tools stitched together. Fix: shared "attention" system — whatever AI focuses on should visibly ripple across all panels simultaneously (subtle, not literal).

**Magic points**

**Zoom levels (strict node budget per level)**
